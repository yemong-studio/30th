# 0. Stitch AI 구현 지시사항

이 문서는 '애매한 삼십대' 공식 웹사이트의 브랜드, 디자인, 페이지 구조, 콘텐츠, 데이터, 운영 및 검증 요구사항을 정의한다. 구현 시 아래 지시를 우선 적용한다.

1. **멀티 페이지 웹사이트로 구현한다.** 하나의 긴 단일 페이지로 모든 기능을 합치지 않는다. HOME, MEMBERS, VIDEOS, COMMUNITY, ABOUT는 각각 독립 페이지로 구성한다. 멤버 상세 및 공지 상세도 독립 URL을 지원한다.
2. **채널 홍보와 구독 전환을 최우선 목표로 한다.** 다만 방문자가 채널의 개성과 콘텐츠를 먼저 경험한 뒤 자연스럽게 유튜브로 이동하도록 구성한다.
3. **실제 인물 사진·실사 출연자 이미지를 사용하지 않는다.** 채널은 얼굴이 노출되는 형식이 아니라 목소리와 게임 플레이를 중심으로 콘텐츠를 제작한다. 마스코트, 게임 플레이 이미지, 썸네일, 음성의 시각화 요소로 표현한다.
4. **멤버별 오리지널 마스코트를 사용한다.** 귀엽고 둥글며 친근한 캐릭터 스타일을 지향한다. 둥글고 큰 머리, 부드러운 실루엣, 친근하고 분명한 표정이라는 스타일 속성을 따르되, 어떤 기존 캐릭터의 외형·표현·디자인도 복제하지 않는다. 특정 기관·브랜드·게임의 캐릭터를 참고 대상으로 지목하지 않는다.
5. **초기 버전에서 YouTube Data API와 별도 백엔드 API를 사용하지 않는다.** 영상 및 공지 정보는 Google Sheets에 직접 등록하고, 공개용 CSV 데이터를 웹사이트가 읽는 방식으로 구현한다. YouTube 영상은 외부 링크로 이동한다.
6. **API 확장 여지는 남긴다.** 현재 API 호출, API 키, 인증, 백엔드 엔드포인트는 구현하지 않는다. 데이터 접근 계층을 화면 코드와 분리하여 향후 API 또는 다른 데이터 공급자로 바꾸기 쉽게 설계한다.
7. **Google Sheets 공개 데이터와 내부 운영 데이터를 분리한다.** 공개 CSV에 내부 메모, 비공개 정보, 계정 정보, 비밀번호, API 키 등을 포함하지 않는다.
8. **확정되지 않은 사실을 만들어내지 않는다.** 멤버 능력치 수치, 게임명·장르, 마스코트 외형, 실제 대사, 채널 연혁, 업로드 일정, 문의 이메일, 미확인 SNS 계정 등은 사용자 확인 또는 실제 자료가 있을 때만 등록한다.
9. **승인되지 않은 기능을 임의로 추가하지 않는다.** 사이트 내 댓글, 오늘의 명대사, 투표, 로그인, 회원가입, 음성 재생, 영상 임베드 플레이어는 초기 범위에 포함하지 않는다.
10. 모바일, 태블릿, 데스크톱에서 모두 사용 가능해야 하며, 페이지 직접 접속·새로고침·뒤로 가기·앞으로 가기를 지원한다.
11. **한국어와 영어를 지원한다.** 한국어가 기본이며 영어 화면 주소는 `/en/`으로 시작한다. 사이트 고정 문구(메뉴·버튼·안내)와 멤버 소개는 영어를 제공하고, 영상 제목·공지 본문은 한국어 원문 그대로 표시한다.
12. **배포는 Netlify 정적 호스팅을 기준으로 한다.** 도메인이 없으므로 `*.netlify.app` 주소로 시작하며, 모든 상세 주소의 직접 접속·새로고침이 되도록 리다이렉트 설정을 포함한다(17.2).
13. **시트에서 불러온 텍스트는 HTML로 해석하지 않는다.** 순수 텍스트(줄바꿈과 링크 자동 변환만)로 표시한다(10.7).

## 1.2 채널 콘셉트

완벽하지는 않지만 퇴근 후 함께 모여 게임할 때는 초등학생 때처럼 몰입하는 30대 친구들의 게임 콘텐츠 채널이다. 게임 플레이, 목소리, 대화, 티키타카, 상황별 반응과 유쾌한 팀플레이가 핵심 콘텐츠다.

채널의 차별점은 출연자의 얼굴이나 실사 모습을 보여주는 것이 아니라, 목소리와 게임 플레이만으로 각 멤버의 개성과 콘텐츠의 재미를 전달한다는 점이다.

기존 메인 문구는 다음을 기본안으로 활용한다.

> 퇴근 후 모인 30대, 승리보다 핑계가 빠르다.

세부 카피는 디자인 작업 중 조정할 수 있으나, 채널의 유쾌한 분위기와 게임 중심 정체성을 유지한다.

## 1.3 사이트 목표 및 우선순위

1. **최우선 목표:** 유튜브 채널 방문 및 구독 유도.
2. **두 번째 목표:** 대표 영상 및 최근 영상 시청 유도.
3. **세 번째 목표:** 7명 멤버의 개성과 마스코트 세계관 전달.
4. **네 번째 목표:** 채널 소식, 공지, 문의 경로 제공.
5. **장기 목표:** 콘텐츠가 늘어나도 쉽게 확장·관리할 수 있는 브랜드 웹사이트 운영.

## 1.4 사이트 맵

주요 페이지는 5개이며, 상세 페이지를 별도 경로로 지원한다.

| 페이지 | URL 예시 | 주요 역할 |
|---|---|---|

# 2. 브랜드 및 디자인 시스템

## 2.1 디자인 방향

**Editorial Gaming** 스타일을 적용한다.

- 미니멀한 레이아웃, 넓은 여백, 비대칭 그리드, 이미지 중심 편집 디자인을 활용한다. (참고 영상 1: 링크와 설명 입력 대기)
- 대형 타이포그래피, 강렬한 시각적 대비, 그래픽 중심 연출을 활용한다. (참고 영상 2: 링크와 설명 입력 대기)
- 참고 영상 링크가 확보되기 전에는 위 속성 표현만을 기준으로 삼는다. 링크가 확보되면 '무엇을 참고하는지' 한두 줄 설명과 함께 이 항목에 추가한다.
- 기존 기획의 게임·픽셀 요소는 핵심 디자인이 아닌 포인트 장식으로 제한한다.
- 전체 인상은 세련된 브랜드 포트폴리오와 유쾌한 게임 채널의 결합이다.

## 2.2 컬러 시스템

| 역할 | 색상명 | HEX |
|---|---|---|
| 기본 배경 | Warm White | `#F6F6F2` |
| 주요 어두운 배경 | Ink Navy | `#151C2B` |
| 주요 강조 | Coral Orange | `#EF684B` |
| 보조 강조 | Electric Yellow | `#FFB800` |
| 보조 컬러 | Soft Sky Blue | `#B9DDE8` |
| 보조 컬러 | Soft Green | `#DCE8D6` |
| 본문 텍스트 | Dark Neutral | `#202124` |
| 보조 텍스트 | Muted Gray | 디자인 시스템에서 대비 기준을 충족하도록 설정 |

밝은 배경을 기본으로 사용하고, HERO 일부·CTA·강조 영역에는 다크 네이비를 활용한다. 컬러를 한 화면에 과도하게 혼합하지 않는다.

### 2.2.1 색 대비 사용 규칙

- 코랄·옐로 배경(버튼, 뱃지 등) 위의 글자는 Ink Navy를 사용한다.
- 밝은 배경 위에서 코랄·옐로는 글자색으로 쓰지 않고 도형, 선, 큰 장식에만 사용한다. (Warm White 위 Coral Orange 글자는 대비가 약 3:1 미만으로, 본문 기준 4.5:1에 못 미친다.)
- Ink Navy 배경 위에서는 코랄·옐로 글자를 사용할 수 있다.
- Muted Gray는 배경 위에서 4.5:1 이상이 되는 값으로 최종 확정한다.

### 2.2.2 멤버 컬러와 배경

- 로마노프(흰색)는 밝은 배경에서, 파르카(검정)는 다크 네이비 배경에서 구분이 어렵다.
- 멤버 카드와 상세 페이지에는 멤버별 배경 톤을 깔아 마스코트가 항상 구분되게 한다.
- 구분을 위한 외곽선은 캐릭터 디자인의 일부로 허용한다(6.6).

## 2.3 타이포그래피 및 레이아웃

- 제목은 크고 굵은 한글 디스플레이 타이포그래피를 사용한다.
- 본문은 가독성 높은 모던 산세리프체를 사용한다.
- 한글 단어가 부자연스럽게 분리되지 않도록 `word-break: keep-all`을 적용한다.
- 넓은 여백과 비대칭 그리드를 적극 활용한다.
- 영상 썸네일과 마스코트 이미지가 콘텐츠의 주인공이 되도록 배치한다.
- 카드 모서리는 기본적으로 부드럽게 처리하되 모든 요소를 과도하게 둥글게 만들지 않는다.
- `word-break: keep-all`은 한국어 화면에 적용하고, 영어 화면은 일반 줄바꿈 규칙과 영문 대응 폰트를 사용한다.
- 폰트 파일은 외부 폰트 서비스(CDN)에서 불러오지 않고 사이트에 직접 포함한다(방문자 IP가 외부로 전달되지 않도록 하고 로딩 성능도 확보).
- 공식 로고 원본이 확보되기 전에는 `애매한 삼십대` 텍스트 기반 임시 워드마크를 사용하고, 최종 로고가 확정되면 교체한다.

## 2.4 픽셀·3D 디자인 사용 원칙

- 픽셀·3D 스타일은 포인트 장식으로만 사용한다.
- 멤버 마스코트는 단순 픽셀 아이콘이 아니라 귀엽고 완성도 있는 오리지널 캐릭터로 제작한다.
- 작은 픽셀 뱃지, 게임 UI 장식, 스탯 아이콘 등에서 제한적으로 활용한다.
- 기존 게임이나 다른 브랜드의 캐릭터를 그대로 사용하지 않는다.

## 2.5 인터랙션 및 모션

자연스럽고 세련된 수준의 애니메이션을 적용한다.

- 스크롤 시 콘텐츠가 부드럽게 등장하는 Scroll Reveal.
- 카드 호버 시 미세한 이동 또는 이미지 반응.
- 버튼 색상 및 상태 전환.
- 페이지 전환 시 짧고 자연스러운 모션.
- 멤버 카드 호버 시 마스코트의 표정 또는 포즈 변경.
- 모바일에서는 호버 대신 탭·진입 상태에 맞춰 동일한 정보를 확인할 수 있도록 한다.
- OS의 `prefers-reduced-motion` 설정을 존중하고 모션 최소화 옵션에서 애니메이션을 줄인다.
- 효과음 및 자동 재생 음성은 초기 버전에서 사용하지 않는다.

# 3. 공통 UI 및 Navigation

## 3.1 데스크톱 헤더

- 왼쪽: 애매한 삼십대 브랜드 로고.
- 메뉴: HOME, MEMBERS, VIDEOS, COMMUNITY, ABOUT.
- 오른쪽: 언어 전환(`KO | EN`)과 유튜브 구독 버튼.
- 현재 페이지 메뉴는 활성 상태로 구분한다.
- 스크롤을 아래로 내리면 헤더를 숨기고, 스크롤을 위로 올리면 다시 나타나도록 한다.
- 페이지 상단에서는 기본적으로 헤더를 표시한다.

## 3.2 모바일 헤더

- 왼쪽: 브랜드 로고.
- 오른쪽: 햄버거 메뉴와 작은 구독 버튼.
- 햄버거 메뉴를 열면 5개 주요 페이지로 이동할 수 있다.
- 언어 전환(`KO | EN`)은 햄버거 메뉴 안 상단에 둔다.
- 작은 화면에서도 메뉴와 구독 버튼이 겹치지 않도록 한다.

## 3.3 Footer

모든 주요 페이지에 공통 Footer를 제공한다.

- 브랜드 로고.
- 간단한 채널 소개.
- 주요 페이지 링크.
- 공식 유튜브 링크.
- 문의 이메일 링크(주소 확정 후 입력).
- 저작권 표기: `© 2026 애매한 삼십대`.
- 개인정보 안내 문구(19.2).
- 언어 전환 링크.

## 3.4 공통 구독 CTA

모든 주요 페이지에서 유튜브 채널로 이동할 수 있는 구독 CTA를 제공한다. CTA는 방문 경험을 방해하지 않도록 배치하며, 페이지 목적에 맞는 문구를 사용한다.

## 3.5 상단 이동

페이지 하단 또는 긴 콘텐츠 영역에서 최상단으로 돌아갈 수 있는 Back to Top 기능을 제공한다.

## 3.6 외부 링크 정책 (확정)

- 유튜브 및 모든 외부 이동은 새 탭으로 연다(`target="_blank"`, `rel="noopener noreferrer"`).
- 외부 링크 아이콘을 표시하고, 스크린리더용으로 '새 탭에서 열림' 안내를 제공한다.
- 모바일에서는 기기 설정에 따라 유튜브 앱이 열릴 수 있다.
- 구독 CTA는 공식 채널 주소 뒤에 구독 확인 팝업 파라미터(`sub_confirmation=1`)를 붙인다. 로그인 상태나 앱 여부에 따라 동작이 달라질 수 있으므로 구현 시 모바일·데스크톱에서 테스트하며, 팝업이 뜨지 않더라도 채널 페이지로는 정상 이동해야 한다.
- 공식 유튜브 주소 원본은 Settings 한곳에서 관리한다.

## 3.7 모바일 하단 구독 바

- 모바일에서 일정 거리 이상 스크롤하면 화면 하단에 얇은 구독 바가 나타난다.
- 닫기 버튼을 제공하며, 닫으면 그 방문 동안은 다시 나타나지 않는다(브라우저 임시 저장 사용, 개인 식별 정보 없음).
- 푸터와 최종 구독 CTA 영역에서는 숨기고, 하단 콘텐츠를 가리지 않도록 여백을 둔다.
- 모션 최소화 설정에서는 애니메이션 없이 표시한다.

## 3.8 언어 전환

- 기본은 한국어이며, 영어는 `/en/` 경로로 제공한다.
- 전환 버튼을 누르면 현재 보던 페이지의 반대 언어 판으로 이동한다.
- 브라우저 언어를 자동 감지해 강제로 이동시키지 않는다.
- `<html lang>` 값은 한국어 `ko`, 영어 `en`으로 설정한다.
- 영어 화면의 HOME(FEATURED VIDEO 근처)과 VIDEOS 상단에 '영상은 한국어로 제작됩니다' 안내를 표시한다. 자막 제공 여부는 확인되지 않았으므로 자막이 있다고 쓰지 않는다.

# 4. HOME 페이지

## 4.1 목적

첫 방문자가 채널의 분위기와 개성을 빠르게 이해하고, 대표 콘텐츠와 최신 콘텐츠를 확인한 뒤 유튜브 채널로 이동하도록 유도한다.

## 4.2 구성 방식

- 대형 타이틀과 멤버 마스코트 비주얼을 결합한 하이브리드 HERO.
- HERO 비주얼은 실제 게임 플레이 영상이 아니라 7명 멤버의 오리지널 마스코트 일러스트 중심으로 구성한다.
- 페이지는 여유 있는 긴 스크롤형으로 구성한다.
- 섹션별로 충분한 여백과 이미지 중심 구성을 적용한다.

## 4.3 섹션 구성

### 01. HERO

- 메인 메시지: `퇴근 후 모인 30대, 승리보다 핑계가 빠르다`를 기본안으로 사용.
- 서브 메시지: 억울한 남탓과 끊이지 않는 티키타카, 7명의 게임 플레이를 소개.
- 채널 성격 라벨: 첫 화면에서 '게임 채널'임을 바로 알 수 있도록 짧은 한 줄 라벨을 둔다. 예: `7명이 함께하는 목소리 중심 게임 채널` / `A voice-driven gaming channel by seven friends` (문구는 승인 필요, 19.2).
- 비주얼: 7명 마스코트의 단체 일러스트 또는 브랜드 그래픽.
- CTA 1: `유튜브 채널 구독하기` → 공식 유튜브 링크.
- CTA 2: `멤버 만나보기` → MEMBERS 페이지.

### 02. FEATURED VIDEO

- 대표 영상은 운영자가 Google Sheets에서 직접 지정한다.
- 대표 영상의 썸네일, 제목, 게임명 및 장르를 표시한다.
- 클릭하면 내부 팝업 플레이어가 아니라 유튜브 원본 영상 링크로 이동한다.
- 대표 영상이 지정되지 않았으면 이 섹션을 숨기거나 안내용 대체 콘텐츠를 표시한다.

### 03. LATEST VIDEOS

- 관리자가 등록한 최신 영상 중 4개를 표시한다.
- 최신 여부는 Google Sheets의 업로드 날짜를 기준으로 판단한다.
- 카드에 표시할 핵심 정보는 영상 제목, 게임명 및 장르다.
- 썸네일과 유튜브 이동 링크를 제공한다.
- 클릭 시 유튜브 원본 링크로 이동한다.
- 전체 영상 탐색 CTA를 VIDEOS 페이지로 연결한다.

### 04. START HERE (처음이라면 이 영상부터)

- 처음 방문한 사람이 채널을 이해하도록 운영자가 지정한 영상(`start_here_order` 1~3)을 최대 3편 노출한다.
- 기존 기획서의 초기 후보 영상을 활용할 수 있다.
- 섹션의 목적이 '처음 방문자 안내'로 분명하므로, FEATURED VIDEO나 LATEST VIDEOS와 같은 영상이 겹쳐도 허용한다. 대신 섹션 제목으로 목적을 분명히 보여준다.
- 지정된 영상이 3편 미만이면 있는 만큼만 보여주고, 하나도 없으면 섹션을 숨긴다.

### 05. MEET THE PLAYERS

- 7명 전체의 마스코트와 활동명을 노출한다.
- 각 카드에서 MEMBERS 또는 해당 멤버 상세 페이지로 이동한다.
- 실제 인물 이미지 사용 금지.

### 06. COMMUNITY PREVIEW

- 최근 공개 공지 일부를 미리 보여준다.
- 공개 공지가 없으면 이 섹션을 숨긴다.
- 공지사항 전체 또는 상세 페이지로 이동할 수 있다.

### 07. FINAL SUBSCRIBE CTA

- 채널의 유쾌한 분위기를 담은 짧은 문구와 유튜브 구독 버튼을 제공한다.
- 버튼은 공식 유튜브 채널로 이동한다.

## 4.4 섹션 최소 노출 조건 (전 페이지 공통)

데이터가 부족할 때 빈 영역이 보이지 않도록 아래 기준으로 숨기거나 축소 표시한다.

| 영역 | 최소 조건 | 조건 미충족 시 |
|---|---|---|
| HOME FEATURED VIDEO | 대표 영상 1개 | 숨김 또는 안내용 대체 콘텐츠 |
| HOME LATEST VIDEOS | 공개 영상 1개 이상 | 있는 만큼 표시(4개 미만 허용), 0개면 숨김 |

# 5. MEMBERS 페이지

## 5.1 목적

7명의 개성을 마스코트와 소개 콘텐츠로 전달하고, 멤버별 출연 영상을 탐색하게 한다.

## 5.2 멤버 기본 정보

실제 이름은 웹사이트에서 사용하지 않는다. 활동명만 공개한다.

| 활동명 | 대표 컬러 | 기존 캐릭터 포지션·특징 |
|---|---|---|
| 예몽 | 민트 | 하이텐션 방랑자. 집중하면 과묵하고 텐션이 오르면 혼잣말과 노래로 오디오를 채우며 퍼즐·퀴즈에 특화된 면이 있다. |
| 뚜기 | 연두 | 상황에 따라 다양한 반응을 보여주는 플레이어. 이 문구를 캐릭터 소개의 기본안으로 사용한다. |
| 보왕 | 골드 | 새침한 브레인. 나긋나긋한 말투 속 새침하고 엉뚱한 매력을 지닌다. |
| 자꾸 | 국방색 | 귀한 레어템 캐릭터. 자주 등장하지 않지만 한마디를 던질 때마다 강한 인상을 남기는 특징이 있다. |
| 파르카 | 검정 | 무결점 하드캐리 고인물. 게임 실력이 뛰어나고 공포게임에서도 침착한 플레이가 특징이다. |
| 산체스 | 보라 | 공인된 놀림감·억울함 요정. 팀원들의 몰이를 받으며 억울해하는 상황이 콘텐츠의 재미 요소다. |
| 로마노프 | 흰색 | 팩폭 및 사운드 효과 담당. 적절한 추임새와 날카로운 게임 평가가 특징이다. |

### 5.2.1 영문 표기와 URL slug

| 활동명 | 영문 표기(초안) | slug |
|---|---|---|
| 예몽 | Yemong | `yemong` |
| 뚜기 | Ttugi | `ttugi` |
| 보왕 | Bowang | `bowang` |
| 자꾸 | Jakku | `jakku` |
| 파르카 | Parkka | `parkka` |
| 산체스 | Sanchez | `sanchez` |
| 로마노프 | Romanov | `romanov` |

영문 표기는 로마자 초안이며, 멤버가 원하는 표기가 있으면 시트의 `display_name_en`에서 바꾼다.

멤버 소개 문구는 위의 확인된 특성을 바탕으로 작성하되, 새로운 성격이나 능력을 사실처럼 추가하지 않는다. 뚜기를 '무서움이 많은 성격' 또는 '놀라는 것을 좋아하는 성격'으로 표현하지 않는다.

## 5.3 멤버 목록 화면

- 7명 전체를 4개 + 3개 비대칭 그리드로 배치한다.
- 카드에는 마스코트, 활동명, 대표 컬러, 한 줄 소개를 표시한다.
- 마우스 호버 시 마스코트가 표정 또는 포즈를 바꾼다.
- 각 카드 클릭 시 멤버별 독립 상세 페이지로 이동한다.

## 5.4 멤버별 상세 페이지

각 멤버에게 독립 URL을 제공한다.

상세 페이지 구성:

1. 멤버의 대표 마스코트 및 컬러.
2. 활동명과 캐릭터 소개.
3. 성격 및 게임 콘텐츠에서 드러나는 특징.
4. 개별 능력치(별 1~5개, 값이 승인·입력된 항목만 표시).
5. 멤버별 출연 영상 목록.
6. 함께 출연한 멤버 및 공동 출연 영상.
7. 이전 멤버 / 다음 멤버 이동.

## 5.5 능력치 시스템

- 모든 멤버에게 동일한 능력치 항목을 강제하지 않는다. 각 멤버의 특징에 맞는 항목을 개별 설정하며, 멤버당 최대 4개로 한다.
- **표현 방식은 게임에서 흔히 쓰는 별(★) 방식으로 확정한다.** 5점 만점, 정수 1~5, 예: ★★★☆☆.
- 접근성을 위해 별과 함께 '5점 만점 중 3점'과 같은 텍스트를 제공한다(색·모양만으로 전달하지 않는다).
- 값이 비어 있는 항목은 숨기고, 임의의 기본값을 표시하지 않는다.
- 시트에는 멤버 본인 확인(5.8)과 운영자 승인을 거친 값만 입력한다. 아래 표의 항목과 별 개수는 **승인 대기 초안**이며, 시트에 입력되기 전에는 사이트에 보이지 않는다.

## 5.6 대표 소개 문구

- 멤버별 대표 대사는 실제 발언인 것처럼 사용하지 않는다.
- 관리자가 별도로 작성한 캐릭터 소개 카피를 사용한다.
- 소개 카피는 한국어와 영어를 함께 관리한다(`intro_copy`, `intro_copy_en`). 초안은 19.2에 있으며 승인이 필요하다.
- 음성 클립 재생 기능은 초기 버전에서 제외한다.

## 5.7 출연 영상 및 멤버 케미

- 영상 등록 시 출연 멤버를 복수 태그로 입력한다.
- Members 페이지는 Videos 데이터의 출연 멤버 태그를 기준으로 해당 멤버의 출연 영상을 자동 분류한다.
- 두 명 이상의 멤버가 한 영상에 태그되면 공동 출연 기록을 자동 계산한다.
- 멤버 상세 페이지에는 함께 출연한 멤버와 관련 영상을 표시할 수 있다.
- 공동 출연은 같은 영상에 함께 등록되었다는 사실만 의미한다. 실제 친밀도, 성격적 궁합, 관계를 임의로 추정하거나 점수화하지 않는다.
- 공동 출연 영역은 함께 출연한 영상이 1편 이상일 때만 표시한다(4.4).

## 5.8 멤버 본인 확인 절차

- 공개 전에 각 멤버 본인이 다음을 확인한다: ① 마스코트 시안 ② 소개 카피(한국어·영어) ③ 능력치 항목과 별 개수 ④ 영상 태그로 노출되는 방식.
- '공인된 놀림감', '억울함 요정'처럼 놀림 요소가 있는 표현은 본인이 명시적으로 동의한 문구만 사용한다.
- 확인 기록은 비공개 문서에 활동명과 확인 날짜만 남긴다(실명 기재 금지).
- 확인되지 않은 항목은 시트에서 `is_visible`을 false로 두거나 값을 비워 사이트에 노출하지 않는다.

## 5.9 뚜기 추가 특징 입력란

- 현재 확인된 특징은 '상황에 따라 다양한 반응을 보여주는 플레이어' 한 가지다.
- 추가 특징은 운영자가 정확한 문구를 제공했을 때만 반영한다. 예를 들어 '하고 싶은 게임이 명확하다' 같은 확인된 취향은 그 문구 수준 그대로 쓴다.
- 확인된 취향을 '무서움이 많다', '놀라는 것을 좋아한다' 같은 성격 해석으로 연결하지 않는다.

# 6. 마스코트 캐릭터 제작 규격

## 6.1 디자인 방향

- 각 멤버의 성격과 콘텐츠 특징을 먼저 해석하고 외형을 자유롭게 창작한다.
- 동물, 몬스터, 상상 속 생명체 등 종류를 미리 제한하지 않는다.
- 7명 모두 같은 세계관과 그림체를 공유하지만 실루엣, 표정, 소품, 비율 등에서 명확히 구분한다.
- 머리가 크고 몸이 작은 귀여운 비율, 둥글고 부드러운 실루엣, 명확한 표정을 지향한다.
- 대표 컬러는 캐릭터의 핵심 색상으로 사용한다.
- 기존 캐릭터를 모방하지 않고 독창적으로 제작한다.
- 실제 멤버의 얼굴·외모를 묘사하거나 실사화하지 않는다.

## 6.2 멤버별 기본 색상

| 활동명 | 컬러명 |
|---|---|
| 예몽 | 민트 |
| 뚜기 | 연두 |

## 6.3 캐릭터 이미지 납품 세트

멤버 1명당 아래 이미지 세트를 제작한다.

- 기본 전신: 투명 배경, 정면 또는 기본 대표 포즈.
- 대표 포즈 변형: 카드 호버 및 주요 섹션 연출에 사용.
- 표정 변형: 서로 구분되는 표정 세트.
- 소형 프로필용 이미지: 작은 카드·배지·메뉴용.
- 필요 시 단체 이미지: HOME HERO 또는 ABOUT에 사용.

**멤버당 최소 납품 수량: 6장** (기본 전신 1 + 호버용 포즈 1 + 표정 3 + 소형 프로필 1). 단체 이미지는 별도로 제작한다.

권장 제작 규격:

- 원본 마스터: 투명 배경 PNG, 정사각형 기준 1024×1024px 이상 권장.
- 웹 배포: PNG 원본을 보존하고 WebP 등 최적화 포맷을 함께 제공할 수 있다.
- 캐릭터 가장자리에 불필요한 배경색·테두리·문자·워터마크를 넣지 않는다. (캐릭터 디자인의 일부로 의도된 외곽선은 허용한다. 6.6 참고)
- 작은 크기에서도 표정과 실루엣이 구분되어야 한다.
- 파일명은 활동명과 용도를 조합해 일관되게 관리한다. 예: `yemong_main.png`, `yemong_hover.webp`.
- 웹 접근성을 위해 캐릭터의 활동명과 용도를 설명하는 대체 텍스트를 한국어·영어로 각각 제공한다.

## 6.4 이미지 사용 위치

| 이미지 | 사용 위치 |
|---|---|
| 기본 전신 | MEMBERS 카드 및 상세 페이지 |
| 대표 포즈 | HOME HERO, ABOUT |

| 소형 이미지 | 뱃지, 프로필, 영상 태그 |
| 단체 이미지 | HOME 및 ABOUT |

## 6.5 제작 방식과 저작권 확인

- 마스코트 제작 주체(외주 일러스트레이터 / 직접 제작 / AI 도구 보조)는 아직 정해지지 않았다.
- 제작 방식을 정하기 전에 저작권 귀속, 상업적 이용 범위, 수정 권한, 크레딧 표기 여부를 확인한다.
- AI 도구를 쓰는 경우 해당 서비스 약관의 상업적 이용 조건을 확인한다.
- 7명의 그림체가 흔들리지 않도록 공통 캐릭터 스타일 가이드(머리 대 몸 비율, 선 굵기, 눈 표현 방식, 그림자 처리)를 먼저 1장 만들고 시작한다.
- Stitch 시안 단계에서는 마스코트 자리에 멤버 대표 컬러의 둥근 실루엣 자리표시자를 쓴다(실사 이미지 금지).

## 6.6 흰색·검정 마스코트 처리

- 로마노프(흰색)와 파르카(검정)는 배경과 섞이기 쉬우므로 멤버별 배경 톤 위에 올린다.
- 구분을 위한 외곽선이나 그림자는 캐릭터 디자인에 포함해 제작한다(후처리로 덧붙이지 않는다).
- 작은 크기(배지·태그)에서도 실루엣이 구분되는지 확인한다.

# 7. VIDEOS 페이지

## 7.1 목적

방문자가 게임, 장르, 출연 멤버, 재미 태그를 이용해 원하는 콘텐츠를 찾을 수 있는 영상 아카이브를 제공한다.

## 7.2 초기 버전 운영 원칙

- YouTube Data API를 사용하지 않는다.
- 별도 백엔드 API를 사용하지 않는다.
- 영상 제목, 게임명, 장르, 업로드 날짜 등은 Google Sheets에 직접 입력한다. 썸네일은 비워두면 7.7 규칙으로 주소를 자동 생성할 수 있다.
- 유튜브 URL을 직접 등록한다.
- 조회수는 초기 버전에서 수집·표시하지 않는다.
- 조회수 자동 갱신 버튼은 구현하지 않는다.
- 영상 클릭 시 유튜브 원본 링크로 이동한다.
- 내부 팝업 플레이어와 영상 임베드는 초기 버전에서 사용하지 않는다.
- API 연동을 위한 데이터 접근 계층의 확장 가능성만 확보한다.

## 7.3 페이지 구성

### 01. VIDEO HERO

- 대형 타이포그래피 및 영상 아카이브 소개.
- 게임 채널 정체성을 보여주는 그래픽을 사용한다.
- 실사 출연자 이미지는 사용하지 않는다.

### 02. FEATURED COLLECTION

- 관리자가 추천 영상으로 지정한 콘텐츠를 노출한다.
- 추천 여부와 노출 순서(`display_order`)는 Google Sheets에서 관리한다.

### 03. VIDEO SEARCH & FILTER

검색 및 필터:

- 영상 제목 검색.
- 게임명 검색.
- 게임 장르 필터.
- 출연 멤버 필터(복수 선택 가능).
- 재미 태그 필터(복수 선택 가능).
- 영상 유형 필터: 전체 / 일반 영상 / Shorts.
- 복수 필터를 동시에 적용할 수 있어야 한다.
- 선택한 필터를 해제하거나 전체 초기화할 수 있어야 한다.
- 검색어·필터·정렬 상태는 주소에 반영한다. 예: `/videos?genre=horror-game&member=sanchez&sort=latest`. 새로고침·뒤로 가기·링크 공유 시 같은 결과가 복원되어야 하며, 존재하지 않는 값이 들어오면 그 값만 무시한다.
- 장르와 재미 태그 이름은 선택한 언어(한국어/영어)로 표시한다(Tags, Genres 시트의 언어별 이름 사용).

### 04. VIDEO GRID

- 썸네일 중심의 반응형 카드 그리드.
- 영상 제목, 게임명 및 장르를 핵심 정보로 표시한다.
- 출연 멤버와 재미 태그도 검색 및 상세 맥락에 활용한다.
- 카드 클릭 시 해당 유튜브 영상 링크로 이동한다.
- 외부 링크임을 시각적으로 알 수 있게 한다. 열기 방식은 3.6 정책(새 탭)을 따른다.
- 카드 비율: 일반 영상은 16:9 가로 카드, Shorts는 9:16 세로 카드로 구분한다. 한 그리드에 섞일 때 Shorts는 별도 줄(작은 세로 카드 행)로 묶어 보여주고, 영상 유형 필터가 Shorts이면 세로 카드 그리드로 표시한다.
- 영상 목록은 '더 보기' 버튼으로 12개씩 추가 로딩한다.

### 05. RELATED VIDEOS

- 게임명, 출연 멤버, 재미 태그의 공통점을 기준으로 관련 영상을 추천한다.
- 추천 대상이 충분하지 않으면 해당 영역을 숨기거나 적은 결과를 자연스럽게 표시한다.
- 관련 영상 썸네일이나 제목을 클릭하면 해당 유튜브 원본 링크로 이동한다.

### 06. SUBSCRIBE CTA

- 영상 탐색 후 공식 유튜브 채널로 이동할 수 있는 구독 CTA를 제공한다.

## 7.4 정렬 방식

| 정렬 | 기준 |
|---|---|
| 최신순(기본) | 업로드 날짜 내림차순 |
| 추천순 | 추천 영상(`is_featured`)을 먼저, 그 안에서 `display_order` 오름차순, 이후 업로드 날짜 내림차순 |

조회수 기준 정렬은 API 미사용으로 제공하지 않는다. 운영자가 정한 순서를 '인기'로 표기하면 방문자가 조회수 기준으로 오해할 수 있으므로 '인기순', 'Most popular' 같은 표현을 쓰지 않는다.

## 7.5 영상 등록 및 관리

영상 등록 시 Google Sheets에 직접 입력한다.

초기에는 URL을 등록하더라도 원격 메타데이터 자동 수집을 하지 않는다(썸네일 이미지 주소 생성은 7.7 참고). URL을 기준으로 관리자가 나머지 정보를 직접 입력한다.

관리 입력 항목:

- 고유 영상 ID.
- 유튜브 URL.
- 영상 제목.
- 썸네일 URL 또는 이미지 경로(선택, 비워두면 7.7 규칙으로 자동 생성).
- 게임명.
- 게임 장르(Genres 시트의 허용 목록에서 선택).
- 출연 멤버(복수).
- 재미 태그(복수, Tags 시트의 허용 목록에서 선택).
- 업로드 날짜.
- 영상 유형(일반 영상 / Shorts).
- 공개 여부.
- 추천 여부.
- 대표 영상 여부.
- 처음이라면 보기 순서(`start_here_order`, 선택).
- 노출 순서.

## 7.6 초기 등록 후보 영상

기존 제미나이 기획서에서 제공한 영상 정보를 초기 등록 후보로 유지한다. 실제 썸네일, 게임명, 장르, 출연 멤버, 재미 태그는 Google Sheets에서 확인·보완한다.

| 초기 제목 | 유튜브 URL |
|---|---|
| 배꼽 빠지는 티키타카 | https://www.youtube.com/watch?v=K06n5hRzXdY |
| 공포게임 비명 혜자 모음 | https://www.youtube.com/watch?v=9TGtkR0Y2Nc |
| 산체스 탈탈 털리는 날 | https://www.youtube.com/watch?v=_NFEC6ysfck |
| waves를 '와베스'라 읽는 예몽이와 그를 구하는 파르카 | https://www.youtube.com/watch?v=bpp-dYeXhIg |

위 영상의 게임명, 장르, 실제 출연 멤버 등 확인되지 않은 필드는 임의로 채우지 않는다.

## 7.7 썸네일 처리

- 시트의 `thumbnail_url`에 값이 있으면 그것을 사용한다(직접 제작한 이미지 포함).
- 값이 비어 있으면 `youtube_url`에서 영상 ID를 읽어 유튜브의 공개 썸네일 이미지 주소(형태: `https://i.ytimg.com/vi/{영상ID}/hqdefault.jpg`)를 만든다. 이것은 YouTube Data API 호출이 아니라 이미지 주소를 사용하는 것이며, 제목·게임명 등 다른 정보는 자동 수집하지 않는다(7.2 원칙 유지).
- 이미지가 불러와지지 않으면 기본 대체 이미지를 표시한다.
- Shorts 썸네일의 비율과 잘림은 구현 단계에서 확인한다.
- 썸네일 사용 권한은 17장 항목으로 운영자가 확인하며, 필요하면 직접 제작한 이미지로 교체한다.

# 8. COMMUNITY 페이지

## 8.1 목적

댓글·투표형 커뮤니티가 아니라 공식 소통 허브로 운영한다. 채널 공지, 공식 외부 채널 연결, 문의 경로를 제공한다.

## 8.2 제외 기능

초기 버전에서 다음 기능은 제공하지 않는다.

- 사이트 내 댓글 작성 및 댓글 수집.
- 오늘의 명대사 및 랜덤 명대사 기능.
- 다음 게임 투표 및 투표 결과.
- 로그인·회원가입 기반 커뮤니티 기능.

## 8.3 페이지 구성

### 01. COMMUNITY HERO

- 공식 소통 공간임을 소개하는 브랜드 메시지.
- 세련된 디자인과 유쾌한 문구를 결합한다.

### 02. NOTICE

- 최신 공지 5개를 표시한다.
- 공개 공지가 5개를 넘으면 '공지 전체 보기' 버튼으로 `/community/notices` 목록 페이지로 이동한다(5개 이하일 땐 버튼 숨김). 목록은 중요 공지(`is_pinned`)를 먼저, 이후 등록일 내림차순으로 보여준다.
- 공개 공지가 하나도 없으면 안내 문구를 보여주고, 아래 소통 안내를 그대로 표시한다.
- 공지 제목, 등록일, 분류, 중요 공지 여부를 표시할 수 있다.
- 각 공지를 클릭하면 독립 공지 상세 페이지로 이동한다.
- 공지 데이터는 Google Sheets에서 관리한다.

### 03. NOTICE DETAIL

- 공지 제목, 등록일, 본문, 관련 링크를 표시한다.
- 공개 여부가 비공개인 공지는 접근할 수 없어야 한다.
- 유효하지 않은 공지 ID는 전용 안내 화면을 표시한다.

### 04. OFFICIAL CHANNELS

- 초기에는 공식 유튜브 링크를 제공한다.
- 추후 다른 SNS가 개설되면 Settings 데이터에 링크를 추가하고 노출할 수 있도록 확장 가능하게 구성한다.
- 아직 제공되지 않은 SNS 링크는 임의로 만들지 않는다.

### 04-1. 소통 안내 (GUIDE)

- 사이트에는 댓글 기능이 없으므로, 영상에 대한 의견은 유튜브 영상 댓글로 남기도록 안내하고 공식 유튜브 링크로 연결한다.
- 문의 종류(일반 문의 / 협업 문의 / 제보·제안)를 안내하고 종류별 메일 버튼을 제공한다.
- 이 섹션은 공지 유무와 관계없이 항상 표시해 공지가 없는 초기에도 페이지가 비어 보이지 않게 한다.

### 05. CONTACT

- 문의 이메일 주소와 문의 버튼을 제공한다.
- 문의 버튼은 설정된 이메일로 연결되는 `mailto:` 방식을 기본안으로 한다. 문의 유형별 버튼은 메일 제목을 미리 채운다(예: `[협업 문의]`, `[제보·제안]`, `[일반 문의]` / 영어 화면: `[Collaboration]`, `[Feedback]`, `[General]`).
- 초기 버전에는 별도 서버 문의 폼이나 개인정보 저장 기능을 만들지 않는다.
- 실제 이메일 주소가 확정되기 전에는 placeholder를 사용하고 가상의 주소를 게시하지 않는다.

### 06. SUBSCRIBE CTA

- 공식 유튜브 채널 구독 링크를 제공한다.

## 8.4 공지 데이터 필드

- `notice_id`: 공지 고유 ID.
- `title`: 공지 제목.
- `content`: 공지 본문.
- `published_at`: 등록일.
- `category`: 공지 분류.
- `is_pinned`: 중요 공지 여부.
- `is_visible`: 공개 여부.
- `link_url`: 관련 외부 링크(선택).
- `sort_order`: 수동 정렬값(선택).

# 10. Google Sheets 데이터 및 운영 구조

## 10.1 기본 원칙

- Google Sheets를 공개 콘텐츠 관리 도구로 사용한다.
- 별도 관리자 웹페이지는 초기 버전에서 만들지 않는다.
- 운영자는 Google Sheets에서 콘텐츠를 직접 등록·수정한다.
- 웹사이트는 공개용 CSV를 읽어 데이터를 표시한다.
- YouTube Data API, 별도 백엔드 API, API 키를 초기 버전에서 사용하지 않는다.
- 데이터 접근 코드를 화면 구성과 분리하여 향후 API 또는 다른 공급자로 변경할 수 있도록 한다.
- 데이터 반영 방식은 '런타임 CSV'(방문자 브라우저가 게시된 CSV를 읽는 방식)로 확정한다(10.8).

## 10.2 공개 데이터와 비공개 데이터 분리

- 공개용 스프레드시트/탭에는 사이트에 노출해도 되는 정보만 입력한다.
- 비공개 운영 자료는 별도의 비공개 스프레드시트에서 관리한다.
- 공개 CSV 주소로 접근할 수 있는 데이터는 누구나 읽을 수 있다고 간주한다.
- 내부 메모, 실제 이름, 비공개 연락처, 비밀번호, 인증정보, API 키를 공개용 데이터에 넣지 않는다.
- 문의 이메일은 사용자가 공개하기로 결정한 공식 문의 주소만 Settings에 입력한다.
- 공개용 CSV 게시 전 공개 범위를 검토한다.

`notice_id`, `title`, `content`, `published_at`, `category`, `is_pinned`, `is_visible`, `link_url`, `sort_order`를 관리한다.

|---|---|---|

### Genres (게임 장르 허용 목록)

필드는 `genre_id`, `label_ko`, `label_en`이다. 초기 목록은 비어 있으며, 확인된 장르만 등록한다. 장르가 지정되지 않은 영상은 장르 표시만 생략한다.

### Check (운영자 점검용, 게시하지 않음)

중복 ID, 잘못된 유튜브 URL, 허용 목록에 없는 태그·장르·멤버 ID, 중복된 `start_here_order`, 날짜 형식 오류를 자동으로 표시하는 수식 탭이다. 공개 CSV로 게시하지 않으며, 게시는 탭 단위로 하므로 이 탭과 내부 메모 탭은 게시 대상에서 제외한다.

## 10.4 데이터 입력 및 검증 규칙

- 고유 ID는 중복될 수 없다.
- 필수 필드가 누락된 행은 공개하지 않거나 해당 행만 제외한다.
- 유튜브 URL 형식과 도메인을 검사한다. 잘못된 URL은 외부 이동 버튼을 비활성화하고 운영자 확인 대상으로 표시한다.
- 영상 유형은 `longform` 또는 `shorts` 중 하나만 허용한다.
- 공개 여부는 명시적으로 설정한다. 공개 여부가 비어 있으면 공개하지 않는 것을 기본으로 한다.
- 출연 멤버 ID는 Members 시트에 존재하는 ID만 허용한다.
- 멤버 ID, 재미 태그 등 복수 값은 구분자를 정해 일관된 형식으로 관리한다.
- 날짜 형식을 통일하고 잘못된 날짜는 정렬 대상에서 제외하거나 검수한다.
- HOME 대표 영상은 한 개를 우선 지정한다. 복수로 지정된 경우 `display_order` 또는 `published_at` 등 명시된 규칙으로 처리하되 운영자 오류 안내를 제공한다.
- 공지 ID는 중복될 수 없고 공개 여부가 true인 공지만 노출한다.
- `start_here_order`는 1~3 범위에서 중복 없이 입력하고 Check 탭에서 검수한다.
- 장르·태그·멤버 ID·영상 유형·공개 여부 칸은 드롭다운(데이터 확인 규칙)으로 제한해 오타를 막는다.
- 복수 값 구분자는 세로선(`|`)으로 통일한다. 예: `yemong|parkka`.
- 날짜 형식은 `YYYY-MM-DD`로 통일한다.

## 10.5 CSV 데이터 연결

- Google Sheets의 공개용 탭을 CSV로 게시한다.
- 웹사이트는 게시된 CSV를 읽고 필요한 데이터 구조로 변환한다.
- 공개 CSV 주소는 환경 설정 또는 데이터 공급자 설정 한곳에서 관리한다.
- CSV 파싱 실패 시 화면 전체가 중단되지 않도록 한다.
- 갱신·캐시 기본값: 방문 중에는 불러온 데이터를 브라우저 임시 저장소에 보관하고 5분마다 새로 확인한다. 연결에 실패하면 마지막으로 정상 수신한 데이터를 사용하고, 그것도 없으면 안전한 빈 상태 안내를 보여준다. 이 저장소에는 방문자 개인정보를 넣지 않는다.
- Google Sheets의 공개 게시 및 반영 지연 가능성을 고려하고, 변경 후 실제 웹사이트에서 반영 여부를 확인한다.
- CSV 방식이 실제 배포 환경에서 CORS, 접근 권한, 게시 지연 등의 이유로 정상 작동하지 않는 경우가 있으므로 개발 초기 배포 환경에서 검증한다. 이 경우에도 사용자 승인 없이 백엔드 API를 추가하지 않는다.

## 10.6 향후 API 확장 구조

현재는 API 기능을 구현하지 않는다. 향후 연결을 고려하여 화면 컴포넌트가 Google Sheets CSV를 직접 파싱하지 않도록 한다.

권장 구조:

`UI Components → Content Data Layer → CSV Provider`

향후 확장 시 `CSV Provider`를 API Provider 등으로 교체할 수 있도록 인터페이스와 데이터 모델을 분리한다. 초기 소스는 CSV만 구현한다. API 키 저장, 인증, 호출, 백엔드 엔드포인트는 범위에 포함하지 않는다.

## 10.7 시트 텍스트 안전 처리

- 시트에서 불러온 모든 텍스트는 화면에 순수 텍스트로만 표시한다. HTML 태그와 스크립트는 해석하지 않는다.
- 줄바꿈은 유지하고 `https://`로 시작하는 주소는 링크로 자동 변환한다.
- 영상·공지·외부 링크와 이미지 주소는 `http://` 또는 `https://`만 허용하고, 그 밖의 형식(예: `javascript:`)은 거부한다.
- 공개 시트가 잘못 수정되더라도 사이트에 악성 코드가 들어가지 않게 하기 위한 장치다.

## 10.8 데이터 반영 방식 결정

- **확정: 런타임 CSV.** 방문자 브라우저가 게시된 CSV를 읽는다. 시트를 고치면 재배포 없이 반영된다(Google 게시 지연으로 몇 분 걸릴 수 있음).
- 한계: 카카오톡·디스코드 같은 앱의 링크 미리보기와 일부 검색 크롤러는 자바스크립트를 실행하지 않아 시트 데이터가 미리보기에 반영되지 않을 수 있다.
- 대응: 주요 5개 페이지와 멤버 상세 7개는 시트와 무관한 고정 제목·설명·대표 이미지를 미리 설정한다. 공지 상세는 공통 제목·이미지를 사용한다(공지 제목은 미리보기에 반영되지 않을 수 있음).
- 향후 배포 시점에 정적 페이지를 미리 생성하는 방식으로 바꿀 수 있도록 데이터 접근 계층(10.6)을 유지한다.

# 12. SEO, 공유 및 접근성

## 12.1 페이지별 SEO

각 주요 페이지와 상세 페이지에 적절한 메타데이터를 설정한다.

- 고유한 페이지 제목(title).
- 페이지별 설명(description).
- Open Graph 제목·설명·이미지.
- 대표 URL(canonical) 설정.
- 페이지 간 내부 링크.
- 필요 시 sitemap 및 robots 설정.
- 언어별 페이지에 `<html lang>`(ko/en)을 설정하고, 같은 페이지의 한국어·영어 판을 서로 연결하는 대체 언어 표시(hreflang)와 언어별 canonical을 설정한다.
- 영어 화면의 title·description·Open Graph는 영어로 작성한다.
- 실제 콘텐츠와 일치하는 제목·설명만 작성한다.

멤버 상세 페이지는 활동명을 중심으로, 영상 목록은 채널 및 영상 탐색 의도를 반영해 메타 정보를 작성한다.

## 12.2 공유 미리보기

- HOME은 공식 브랜드 대표 이미지.
- MEMBERS는 멤버 마스코트 단체 이미지, 멤버 상세 7개는 멤버별로 미리 설정한 고정 이미지와 문구.
- VIDEOS는 영상 또는 채널 아카이브 대표 이미지.
- COMMUNITY 공지 상세는 공통 공지 대표 이미지와 고정 문구(10.8: 공지 제목은 일부 앱의 미리보기에 반영되지 않을 수 있음).
- ABOUT은 채널 마스코트 단체 이미지.

## 12.3 접근성

- 키보드로 메뉴, 버튼, 링크, 필터를 사용할 수 있어야 한다.
- 포커스 상태가 시각적으로 구분되어야 한다.
- 이미지에 의미 있는 대체 텍스트를 제공한다.
- 색상만으로 정보 상태를 구분하지 않는다.
- 텍스트와 배경의 대비를 확보한다.
- 터치 요소는 모바일에서 누르기 쉬운 크기로 만든다.
- 모션 최소화 설정을 존중한다.
- 링크는 어디로 이동하는지 알 수 있는 문구를 사용한다.
- 별 능력치는 '5점 만점 중 N점' 텍스트를 함께 제공한다.
- 새 탭으로 열리는 링크는 스크린리더용 안내를 제공한다(3.6).
- 언어 전환 버튼은 현재 언어를 표시하고 키보드로 사용할 수 있어야 한다.

# 13. 개인정보 및 문의 운영

- 초기 버전에서 로그인·회원가입을 제공하지 않는다.
- 사이트 내부 댓글·투표·사용자 게시물 기능이 없으므로 해당 이용자 콘텐츠 DB를 만들지 않는다.
- 문의는 공개된 공식 이메일로 연결하는 `mailto:` 방식을 기본으로 한다.
- 문의 메일 주소는 사용자 확인 후 입력한다.
- 문의 버튼 클릭만으로 사이트가 문의자의 개인정보를 저장하지 않도록 한다.
- 외부 유튜브 및 SNS 이동 시 외부 사이트로 이동한다는 점을 명확히 한다.
- 분석 도구, 광고 추적, 쿠키 기반 추적 기능은 별도 승인 전에는 추가하지 않는다.
- 공개 데이터에 실제 멤버 이름이나 내부 개인정보를 포함하지 않는다.
- 폰트와 이미지는 사이트에 직접 포함해 불필요한 외부 서비스 요청을 줄인다. (영상 썸네일은 유튜브 이미지 주소에서, 콘텐츠 데이터는 Google Sheets 게시 CSV에서 불러온다.)
- 푸터에 개인정보 안내 문구를 둔다(19.2). 문구는 '회원가입·댓글·문의 폼 등으로 개인정보를 수집하지 않는다'는 사이트 기능 기준으로 쓰고, 호스팅 서비스의 기본 접속 기록까지 부정하는 표현은 쓰지 않는다.

## 13.1 분석 도구 (승인 대기, 기본 OFF)

- 현재는 방문·클릭을 측정할 수단이 없어 구독 전환 성과를 알 수 없다.
- 도입한다면 쿠키를 쓰지 않는 간단한 분석 도구를 후보로 하며, 별도 승인 전에는 설치하지 않는다.
- 승인 시 개인정보 안내 문구도 함께 수정한다.

# 14. 반응형 및 성능 요구사항

## 14.1 반응형

- 모바일, 태블릿, 데스크톱 레이아웃을 지원한다.
- 모바일 메뉴는 햄버거 메뉴로 제공한다.
- MEMBERS 카드는 모바일에서 읽기 쉬운 1~2열로 재배치한다.
- VIDEOS 카드와 필터는 화면에 맞게 재배치하고 모바일에서 필터 조작이 편해야 한다.
- 큰 타이포그래피는 작은 화면에서 줄바꿈·축소가 자연스럽게 처리되어야 한다.
- 이미지가 화면 밖으로 넘치거나 수평 스크롤이 발생하지 않도록 한다.
- 영어 문구가 한국어보다 길어져도 메뉴·버튼·카드가 깨지지 않아야 한다.

## 14.2 이미지와 성능

- 이미지 용량을 최적화한다.
- 화면 하단의 이미지에는 지연 로딩을 적용한다.
- 이미지 크기 및 비율을 사전에 지정해 레이아웃 이동을 줄인다.
- 썸네일·마스코트에 적절한 해상도의 웹용 파일을 사용한다.
- 애니메이션은 부드럽고 짧게 유지하며 과도한 3D 효과를 사용하지 않는다.
- CSV 데이터 로딩 중에는 로딩 상태를 보여준다.

# 15. 최종 콘텐츠 및 운영 정책

## 15.1 콘텐츠 작성 원칙

- 실제 확인된 채널 및 멤버 정보만 사용한다.
- 실제 멤버의 이름은 사용하지 않고 활동명만 사용한다.
- 실제 발언이 아닌 소개 문구를 실제 대사처럼 표시하지 않는다.
- 영상의 게임명·장르·출연 멤버를 추측해서 채우지 않는다.
- 실제 공지와 날짜를 임의로 만들어 공개하지 않는다.
- 가상의 조회수, 구독자 수, 업로드 주기, 연혁을 표시하지 않는다.

## 15.2 영상 운영

- 영상 등록은 Google Sheets에서 직접 한다.
- 제목, 게임명, 장르, 업로드 날짜, 출연 멤버, 태그, 영상 유형을 수동 입력한다. 썸네일은 직접 입력하거나, 비우면 자동 생성한다.
- 최신 영상은 업로드 날짜 기준으로 4개를 HOME에 노출한다.
- 대표 영상은 관리자가 지정한다.
- 조회수는 초기 버전에서 수집하거나 표시하지 않는다.
- 정렬은 최신순과 추천순만 제공한다(인기순은 제공하지 않음).
- 추천순은 관리자가 추천 표시를 활성화한 영상을 먼저 보여주는 방식이다.
- 'START HERE'는 `start_here_order`로 지정한다.
- 카드 클릭 시 유튜브 원본 링크로 이동한다.

## 15.3 공지 운영

- 공지 데이터는 Google Sheets에서 관리한다.
- COMMUNITY에는 최신 공개 공지 5개를 노출한다.
- 공지 상세 페이지는 독립 URL을 가진다.
- 공개 여부가 false인 공지는 화면에서 제외한다.

## 15.4 언어 운영

- 한국어가 기본이며, 영어는 사이트 고정 문구와 멤버 소개에 제공한다.
- 영상 제목·게임명·공지 본문은 한국어 원문 그대로 표시한다. 영어 화면에 한국어 콘텐츠가 섞여 보이는 것은 정상이며, 이를 안내하는 문구를 둔다(3.8).
- 영어 문구는 초안(19.1, 19.2)이므로 운영자 승인 후 사용하고, 필요하면 원어민 검수를 받는다.

## 17.1 기술 선택에 대한 원칙

프레임워크, 호스팅, 도메인은 아직 정해지지 않았다. 따라서 이 문서는 특정 기술을 임의로 강제하지 않는다. 다만 어떠한 기술을 선택하더라도 다음 조건은 유지해야 한다.

- 멀티 페이지 직접 접속 및 새로고침 지원(`/en/` 경로 포함).
- 정적 프런트엔드로 시작할 수 있는 구조.
- Google Sheets 공개 CSV 연결.
- 초기 YouTube Data API 및 별도 백엔드 API 미사용.
- 향후 API 공급자로 교체 가능한 데이터 접근 계층.
- 모바일 및 접근성 기준 충족.

## 17.2 Netlify 배포 조건

- 멤버·공지 상세와 영어 경로(`/en/...`)를 주소창에 직접 입력하거나 새로고침해도 해당 페이지가 열리도록 Netlify 리다이렉트 설정을 포함한다.
- 존재하지 않는 주소는 전용 404 화면(한국어·영어)을 보여준다.
- 초기 주소는 `*.netlify.app`이다. 도메인을 구매하면 연결할 수 있고, 주소가 바뀌면 canonical과 공유 미리보기 주소도 함께 갱신한다.
- 배포 파일에 API 키·비밀번호 같은 비밀값을 넣지 않는다(초기에는 해당 값 자체가 없다).
- 공개 CSV 주소는 설정 한곳에서 관리한다.

# 최종 구현 원칙 요약

애매한 삼십대 웹사이트는 세련된 Editorial Gaming 디자인을 바탕으로 HOME, MEMBERS, VIDEOS, COMMUNITY, ABOUT의 5개 주요 페이지와 멤버·공지 상세 페이지로 구성한다. 7명은 활동명과 대표 컬러를 기반으로 한 독창적인 귀여운 마스코트로 표현한다. 채널은 목소리와 게임 플레이 중심이므로 실사 인물 이미지를 사용하지 않는다. 사이트는 한국어(기본)와 영어를 지원하며 Netlify에 배포한다.

초기 운영은 Google Sheets에서 공개 콘텐츠를 직접 관리하고, 공개용 CSV를 통해 웹사이트에 반영한다. YouTube Data API와 별도 백엔드 API는 사용하지 않으며, 영상은 유튜브 원본 링크로 이동한다. 향후 API를 도입할 수 있도록 데이터 접근 계층만 분리한다. 실제 확인되지 않은 멤버 정보, 능력치, 연혁, 이메일, SNS, 영상 메타데이터는 임의로 생성하지 않는다.

**본 문서는 사용자가 승인한 기획 결정을 통합한 최종 상세 기획서이며, 제17장의 미확정 입력 항목은 실제 자료 확보 및 개발 환경 결정 후 채운다.**

# 20. 기획 완료 후 다음 단계 및 실행 로드맵

본 문서는 기획 단계의 기준 문서다. 기획서 작성이 끝났다고 해서 웹사이트 제작과 배포가 완료된 것은 아니다. 다음 단계는 아래 순서로 진행하며, 각 단계의 산출물을 확인한 뒤 다음 단계로 이동한다. 사용자가 승인하지 않은 기능이나 콘텐츠를 임의로 추가하지 않는다.

## 20.1 단계별 진행 순서

## 20.2 Stitch AI 제작 프롬프트 작성 원칙

1. 본 최종 기획서를 프로젝트의 기준 문서로 사용하고, 복붙용 프롬프트는 별도 파일 `amber30s_stitch_prompts.md`를 사용한다.
2. 전체 공통 지침, 디자인 시스템, 공통 헤더·푸터를 먼저 전달한다.
3. HOME, MEMBERS, VIDEOS, COMMUNITY, ABOUT 순서로 페이지별 프롬프트를 분리해 제작한다.
4. 멤버 상세 페이지와 공지 상세 페이지의 레이아웃 및 경로도 빠뜨리지 않는다.
5. 실제 자료가 없는 콘텐츠는 임의의 실사 사진, 가짜 댓글, 가상의 능력치, 허구의 연혁으로 채우지 않는다. 필요한 경우 명확히 구분된 자리표시자 또는 빈 상태 화면을 사용한다.
6. Stitch에서 생성된 결과가 모든 데이터·라우팅·배포 요구사항을 자동으로 충족한다고 가정하지 않는다. 별도 구현 및 검수가 필요한 항목을 확인한다.
7. 수정 요청 시 사용자가 지정한 부분만 변경하고, 승인된 나머지 화면과 기능은 유지한다.

## 20.3 초기 개발 범위 재확인

다음 단계에서도 초기 개발 범위는 변경하지 않는다.

- YouTube Data API 호출 금지.
- 별도 백엔드 API 및 자체 데이터베이스 서버 도입 금지.
- 영상은 외부 유튜브 링크로 이동.
- Google Sheets 공개 CSV를 콘텐츠 데이터 공급원으로 사용.
- 공개 데이터와 내부 관리 데이터 분리.
- 관리자 전용 웹페이지, 로그인, 댓글, 투표, 음성 재생, 영상 임베드 플레이어 미구현.
- 향후 API를 위한 데이터 접근 계층의 분리만 허용하며 실제 API 연동은 별도 승인 후 진행.

## 20.4 다음 단계의 첫 작업

기획 완료 직후 시작할 작업은 **Stitch AI용 제작 프롬프트 구성**이다. 이때 제17장의 미확정 항목은 모두 준비될 때까지 제작을 중단해야 한다는 의미가 아니다. 실제 자료가 필요한 항목은 자리표시자 또는 비노출 상태로 두고, 확정된 디자인과 기능부터 화면 시안을 제작할 수 있다.

첫 제작 순서는 다음과 같다.

1. 공통 디자인 시스템과 헤더·푸터 시안.
2. HOME 페이지 시안.
3. MEMBERS 목록 및 멤버 상세 시안.
4. VIDEOS 아카이브 시안.
5. COMMUNITY 공지 목록 및 공지 상세 시안.
6. ABOUT 페이지 시안.
7. 영어 화면 시안(공통 UI와 HOME 중심으로 확인).
8. 모바일 화면과 공통 반응형 시안.

화면 시안 검토가 끝나면 구현 환경을 결정하고, 제20.1절의 나머지 단계에 따라 구현·데이터 연결·검수·배포를 진행한다.

## 20.5 진행 순서 쉬운 요약

1. Stitch에 프롬프트를 순서대로 붙여넣어 화면 디자인을 만든다.
2. 디자인을 확인하고 고칠 곳은 '수정 요청 문구'(프롬프트 파일에 있음)로 요청한다.
3. 디자인이 확정되면, 구글 시트에서 영상·공지를 불러오는 기능과 페이지 이동을 붙이는 구현 단계를 진행한다. (Stitch는 화면 디자인을 만드는 도구이므로 이 단계는 별도로 필요하다.)
4. 완성된 사이트를 Netlify에 올리면 `이름.netlify.app` 주소가 생긴다.
5. 도메인을 구매하면 나중에 연결한다.
